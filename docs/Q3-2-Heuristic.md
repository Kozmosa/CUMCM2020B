# Q3.2 有限策略 Monte Carlo 简化方案

> 本文是 [`Q3-2-Solve.md`](./Q3-2-Solve.md) 的有损简化说明。
>
> `Q3-2-Solve.md` 仍定义完整的有限时域随机博弈、精确状态、阶段纳什均衡和全动作 regret 认证语义；本文只说明 `--backend heuristic` 为了在竞赛级时间内得到可解释策略，具体删除、替换和近似了哪些部分。

---

## 1. 为什么增加简化后端

完整 `adaptive` 实验从 2026-07-28 23:55 运行到 2026-07-29 10:26，随后按人工请求通过 `SIGTERM` 安全停止。求解器完成了原子检查点并输出 `SEARCH_STOPPED`：

| 指标 | 停止时数值 |
|---|---:|
| 墙钟时间 | 38,095 秒，约 10.58 小时 |
| 非终止缓存状态 | 5,131,301 |
| 终止叶结算 | 138,876,780 |
| 总状态求值计数 | 144,008,081 |
| 候选联合 profile | 163,068,541 |
| 完整单边偏离上界扫描 | 180,405,027,690 |
| 精确展开偏离 | 132,434,229 |
| 峰值 RSS | 约 7.07 GiB |
| 检查点 | 约 1.8 GiB |
| 根状态策略 / regret | 尚未得到，仍为无穷 gap |

检查点保存在 `q3/output/level6-formal/checkpoint`，可按 `result.json` 中的 `resume_command` 恢复。此次暂停不表示精确算法错误，只说明“为每一个公开状态求阶段均衡，再对完整动作空间认证最佳反应”的目标显著强于竞赛论文通常需要的代表性策略。

因此新增第三条求解路径：

```text
exact       完整枚举和完整均衡选择
adaptive    受限博弈 + 完整单边偏离认证
heuristic   有限完整策略库 + Monte Carlo 经验博弈
```

`heuristic` 的目标是在分钟级到小时级预算内给出：

1. 三名玩家可直接执行的路线、购买和挖矿策略；
2. 正确多人规则下的期望支付与成功率估计；
3. 对有限策略库中单边换策略的经验 regret；
4. 明确的统计置信区间和适用范围。

它不再尝试证明完整动作空间中的马尔可夫完美均衡。

## 2. 从完整模型保留的内容

简化后端复用 `q3.transition`，没有另写一套近似游戏规则。以下语义与 `Q3-2-Solve.md` 完全一致。

### 2.1 三人完整资源和现金状态

每名玩家仍保存：

```text
(status, position, water, food, cash_scaled, fixed_payoff_scaled)
```

水、食物和现金不量化，不合并相邻状态。金额继续使用 `money_scale = 6` 的整数定点表示，三人平分矿山收入时不会因为浮点舍入改变支付。

### 2.2 正确的联合交互规则

每个模拟日仍同步生成三名玩家行动，然后由统一联合转移处理：

- 只有同一天走同一条有向边 `A -> B` 的玩家才构成道路拥堵；
- 道路消耗倍率为 `2k`；
- 同矿挖矿时每人消耗三倍资源并获得 `R/k`；
- 同村正购买人数不少于两人时使用四倍基准价格；
- 沙暴禁止移动，但允许停留和挖矿；
- 到达终点立即吸收，并按半价退回剩余物资；
- 失败玩家立即吸收，支付为当时现金减去 `M`。

这与仅根据“是否位于同一区域”估计交互不同，也不会忽略第三名玩家。

### 2.3 天气信息结构

未来天气继续服从配置中的 i.i.d. 分布。策略在第 `t` 天只根据：

- 当前公开联合状态；
- 当天已经观察到的天气；
- 自己已执行的挖矿天数；

决定当日行动。策略函数不会读取天气样本的未来部分。完整天气序列只由外层模拟器保存，用来按日向策略提供当前天气。

### 2.4 支付目标

默认继续估计 `Q3-2-Solve.md` 的惩罚期望支付：

$$
G_{i,M}
=
\begin{cases}
C_{i,\tau_i}+\frac12p_WW_{i,\tau_i}+\frac12p_FF_{i,\tau_i},
&\tau_i\le T,\\
C_{i,\kappa_i}-M,
&\text{失败}.
\end{cases}
$$

`--penalty`、`--p-storm` 和基础资源参数仍由统一 `Q3Config` 控制。

## 3. 相对 `Q3-2-Solve.md` 的核心简化

| 完整模型 | `heuristic` 替代 | 影响 |
|---|---|---|
| 任意公开联合状态上的反馈策略 | 有限个参数化完整策略 | 未生成策略库外的行为 |
| 每日重新选择任意路线 | 第 0 天承诺一条路线模板 | 保留天气、资源和失败反馈，但不重新规划主路线 |
| 全部整数初始购买 | 每条路线自动生成少量安全系数购买 | 可能遗漏更优水食配比 |
| 村庄全部整数购买 | 补充到固定目标库存 | 不优化每个村庄状态的精确购买量 |
| 任意挖矿/停留序列 | 固定目标挖矿天数 | 不搜索复杂的天气条件挖矿阈值 |
| 所有未来天气分支精确期望 | 有限个共同随机天气样本 | 支付和 regret 存在采样误差 |
| 每个状态求阶段 Nash | 对完整策略做一次有限正规形博弈 | 不保证子博弈精炼或离轨最优性 |
| 完整个人动作最佳反应 | 只允许换成策略库内另一完整策略 | regret 只对有限策略库有效 |
| 向上舍入证明界 | 正态近似置信区间 | 是统计区间，不是确定性证书 |
| v2 递归状态检查点 | 不保存检查点 | 计算较短，重新运行即可复现 |

最重要的语义变化是：

> 完整后端的一个“行动”是某日某状态下的水食购买和主要动作；简化后端经验博弈中的一个“行动”是一整套 30 天完整策略。

因此简化后端不再构造数百万个公开状态，也不在每个状态重复求三人阶段均衡。

## 4. 有限策略的定义

公开类型 `HeuristicPolicy` 包含：

```text
name
family
route
initial_water, initial_food
mine_days
village_water_target, village_food_target
safety_factor
```

### 4.1 路线族

默认策略库从以下 waypoint 族生成最短简单路径：

1. `direct`：起点直接到终点；
2. `village14`：先到村庄，再到终点；
3. `mine18`：先到矿山，再到终点；
4. `village14-mine18`：先村庄补给，再到矿山和终点。

每个路线族默认保留两条拓扑不同的最短路径。路径生成器会优先覆盖不同的第一跳，因此第六关策略库同时含有 `1 -> 2` 和 `1 -> 6` 两个方向，避免所有策略只是在同一路线上改变资源量。

路线是主移动计划，不是无条件逐日行动：

- 沙暴日不会移动；
- 到矿山且尚未完成目标挖矿天数时选择挖矿；
- 在村庄按目标库存购买；
- 资源不足以执行预定移动或挖矿时，确定性回退为停留；
- 连停留也不可行时选择失败吸收动作。

三名玩家的预定动作先同时生成，再根据实际同边人数、同矿人数和同村购买人数检查可行性。回退后重新计算交互人数，直到得到合法联合行动。这一步只改变启发式策略的行动选择，最终结算仍使用精确联合转移。

### 4.2 初始资源量

对移动日，先估计完成一次有效移动所需的平均资源。设沙暴概率为 `p_s`，资源基础消耗为 `c_theta`，则：

$$
\bar c_{\mathrm{move}}
=
\frac{\sum_{\theta\ne s}p_\theta 2c_\theta}{1-p_s}
+
\frac{p_s c_s}{1-p_s}.
$$

第一项是非沙暴日移动的条件平均双倍消耗，第二项是等待一次成功移动前预计经历的沙暴停留消耗。

挖矿一天的平均资源为：

$$
\bar c_{\mathrm{mine}}=\sum_\theta p_\theta 3c_\theta.
$$

若路线在第一次到达村庄前有 `d` 次移动和 `m` 次挖矿，初始购买目标为：

$$
(W_0,F_0)
=
\left\lceil
s\left(d\bar c_{\mathrm{move}}+m\bar c_{\mathrm{mine}}\right)
\right\rceil,
$$

其中 `s` 是安全系数。默认策略库优先包含低载荷 `s=1.0` 和接近满载的 `s=2.5`，在扩大策略数时再加入中间值 `s=1.75`。

目标超过负重或现金限制时按水食比例缩放，并逐箱修正到严格可行。

### 4.3 村庄补给

经过村庄的策略只为“到达第一个村庄前”的路段购买初始资源；到村庄后再补到剩余路线的目标库存。

为了消除“其他玩家是否同时购买”造成的行动可行性循环，启发式购买量始终按最不利的四倍价格检查现金。若实际只有一名玩家购买，精确转移会按两倍价格结算，因此策略仍然合法，但可能比完整模型保守。

### 4.4 挖矿配额

默认矿山路线包含 `2` 天和 `4` 天挖矿候选。策略在已观察天气下执行：

- 非沙暴：未完成配额则挖矿，否则继续路线；
- 沙暴：未完成配额则挖矿，否则停留。

它没有搜索“资金、库存、日期、天气”联合阈值下的最优挖矿规则。

## 5. Monte Carlo 经验博弈

设生成的完整策略库为：

$$
\Pi=\{\pi^1,\ldots,\pi^K\}.
$$

三名玩家的有限正规形博弈包含 `K^3` 个策略 profile。对每个 profile 和共同天气样本 `omega_e`，使用正确联合模拟器得到：

$$
G_i(\pi_a,\pi_b,\pi_c;\omega_e).
$$

经验支付为：

$$
\widehat U_i(a,b,c)
=
\frac1N\sum_{e=1}^N
G_i(\pi_a,\pi_b,\pi_c;\omega_e).
$$

所有 profile 使用同一组天气样本。这种 common random numbers 设计使两个策略的支付差可以逐样本配对，显著降低经验 regret 的方差。

### 5.1 玩家置换对称性

初始状态、策略库和规则对玩家编号对称，因此程序只实际模拟：

```text
a <= b <= c
```

的组合，再通过玩家置换填充完整 `K^3` 支付张量。该操作不近似支付，只避免重复模拟等价的玩家编号排列。

默认 `K=16` 时：

```text
完整 profile 数        16^3 = 4096
实际模拟的对称 profile C(18, 3) = 816
```

### 5.2 经验纯均衡

在经验均值张量上完整检查有限策略库的纯最佳反应。允许 `--heuristic-pure-tolerance` 元以内的样本均值差视为经验无差异。

若存在多个经验纯均衡，沿用完整后端的主要选择顺序：

1. 总成功率；
2. 最低玩家支付；
3. 总支付；
4. 策略编号字典序。

若 `--equilibrium pure` 且没有经验纯均衡，程序穷举选择最大单边经验 regret 最小的纯 profile，并标记为 `minimum-regret-pure`。

### 5.3 经验混合均衡

若选择 `pure-mixed` 且没有经验纯均衡，程序在有限策略支付张量上最小化 NashConv，得到三名玩家各自对完整策略的独立混合分布。

这是连续非凸优化结果，只是局部精修；`selection_complete_within_library=false`。它与完整模型中的“每个状态混合当前行动”不同，这里混合的是整套路线策略。

## 6. 经验 regret 和置信区间

固定有限策略混合 `sigma` 后，玩家 `i` 对策略库内纯偏离 `pi^d` 的样本差为：

$$
D_{i,d,e}
=
G_i(\pi^d,\sigma_{-i};\omega_e)
-
G_i(\sigma;\omega_e).
$$

程序报告：

```text
empirical_policy_regret_mean
player_regret_lower
player_regret_upper
max_regret_lower
max_regret_upper
```

上下界使用配对差的正态近似，并对 `玩家数 x 策略数` 次偏离比较进行 Bonferroni 修正。

由于失败罚金 `M=10^6` 会形成重尾、稀有失败样本，少量 episode 下 regret 上界可能很宽。增加 `--heuristic-episodes` 会缩小统计误差，但无论样本量多大，它仍然只覆盖策略库内偏离。

报告中必须同时出现：

```json
{
  "regret_scope": "generated_finite_policy_library",
  "full_action_regret_certified": false
}
```

不得把该 regret 与 `adaptive` 的完整个人动作 regret 上界混用。

`value_lower/value_upper` 同样是策略混合支付均值的统计置信区间，不是 Bellman 或最佳反应证明界。

## 7. 状态和结果语义

简化后端新增状态：

| 状态 | 含义 |
|---|---|
| `HEURISTIC_PURE` | 已完整扫描有限策略库的经验纯均衡，或选择有限库最小 regret 纯 profile |
| `HEURISTIC_MIXED` | 在有限策略库上得到 NashConv 局部混合解 |
| `SEARCH_STOPPED` | 墙钟、RSS 或取消信号中断经验 profile 模拟 |

即使有限策略库被完整扫描：

```text
selection_complete = false
```

因为该字段仍保留 `Q3-2-Solve.md` 中“完整原问题均衡选择是否完成”的含义。有限库内部扫描状态单独记录为：

```text
policy.selection_complete_within_library
```

结果中的 `policy` 包含：

- 每名玩家的有限策略支持和概率；
- 完整生成策略库及其路线、购买、挖矿参数；
- 最大概率策略组成的代表性 profile；
- 第一个共同天气样本；
- 对应的逐日行动、资源、现金和吸收状态回放。

代表性回放用于解释策略，不等于支付均值轨迹。

```bash
.venv/bin/python -m q3.solve_q3_2 \
  --backend heuristic --mode level6-initial \
  --heuristic-episodes 50 \
  --heuristic-max-policies 16 \
  --heuristic-route-variants 2 \

  --output q3/output/q3_2_heuristic_probe
```

建议正式简化计算：

```bash
.venv/bin/python -m q3.solve_q3_2 \
  --backend heuristic --mode level6-initial \
  --penalty 1000000 --p-storm 0.10 \
  --heuristic-episodes 2000 \
  --heuristic-confidence 0.95 \
  --heuristic-max-policies 16 \
  --heuristic-route-variants 2 \
  --heuristic-pure-tolerance 5 \
  --equilibrium pure-mixed \
  --seed 20260728 \
  --wall-hours 2 --memory-gib 16 \
  --output q3/output/q3_2_heuristic
```

`heuristic` 当前使用一个 Python worker。它不接受：

```text
--checkpoint
--resume
--mode level6-state
```

`--bound-threads`、购买格点 oracle 和完整状态数上限也不参与该后端。

## 9. 复杂度和实测

令策略数为 `K`、天气样本数为 `N`、平均实际游戏天数为 `L`。利用三人置换对称性后的模拟复杂度约为：

$$
O\left({K+2\choose3}NL\right).
$$

一次开发 probe 使用：

```text
K = 16
N = 50
实际对称 profile = 816
逐日联合转移 = 433,606
墙钟时间约 12.6 秒
峰值 RSS 约 166 MiB
```

该 probe 的代表性 profile 为：

```text
玩家 1：高载荷矿山路线
玩家 2：高载荷村庄—矿山路线
玩家 3：高载荷直达路线
```

50 个天气样本下三名玩家成功率均为 1，但样本数太少，失败罚金导致经验 regret 置信上界仍很宽。该结果只用于验证实现吞吐，不作为最终数值结论。

默认 `N=500` 的预计运行时间为数分钟而不是数小时；正式报告仍应记录实际机器、随机种子和完整输出。

## 10. 明确没有解决的问题

`heuristic` 不支持以下结论：

1. “结果是完整第六关的纳什均衡”；
2. “任意单日购买或移动偏离收益不超过 10 元”；
3. “策略在所有离轨公开状态都最优”；
4. “不存在策略库外更好的路线、购买或天气阈值”；
5. “统计置信区间是确定性的价值或 regret 证明界”。

可以支持的准确表述是：

> 在给定参数化策略库和 i.i.d. 天气模型下，使用共同随机天气样本估计了完整多人规则的经验支付，并求得有限策略博弈中的经验纯/混合均衡及策略库内偏离 regret。

若需要增强结果，可依次扩展：

1. 增加路线变体和安全系数；
2. 增加挖矿天数及村庄库存目标；
3. 根据当前对手位置动态选择等长下一跳；
4. 使用经验最佳反应生成新策略，形成 PSRO/double-oracle；
5. 对最终少量候选状态调用 `adaptive` 完整偏离 oracle 做局部审计。

最后两项可以逐步连接竞赛级经验解和研究级完整认证，而不必重新展开整个根状态空间。

## 11. 验证范围

自动测试覆盖：

- 第六关默认策略库有界、路线合法，并覆盖 `1 -> 2` 与 `1 -> 6`；
- 策略库包含矿山和村庄补给策略；
- 单人一日回放与精确联合转移、终点退款一致；
- 固定随机种子重复求解得到相同策略和数值；
- 经验纯策略选择能排除确定失败策略；
- 取消预算返回 `SEARCH_STOPPED`，且不声称存在检查点；
- 原 `exact|adaptive` 测试和 CLI 继续兼容。

简化后端刻意不与 `exact` 在完整第六关上比较，因为两者求解的策略空间不同。小关卡只能验证规则模拟和有限经验博弈逻辑，不能把启发式策略库等同于完整动作空间。
