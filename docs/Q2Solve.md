# Q2 实现说明

> 对应题目：一名玩家，**仅知道当天天气**，未来天气 i.i.d.，求最优策略；求解附件「第三关」「第四关」。  
> 数学模型见 [`Solution/Q2.md`](./Solution/Q2.md)。  
> 代码目录：[`q2/`](../q2/)。

---

## 1. 问题要点（实现视角）

Q2 与 Q1 的唯一区别是**天气信息结构**：第 `t` 天行动前只能观察当天天气 `θ_t`，未来天气独立同分布 `p(θ)`。其余规则（消耗、负重、村庄 2× 价格、矿山收益、终点半价退款、截止日 `T`）全部与 Q1 一致。

| 要素 | 实现处理 |
|------|----------|
| 行动前已知当天 `θ_t` | 每个 `(t, v)` 对每种 `θ` 分别取 `max_a`，再按 `p(θ)` 加权 |
| 未来天气未知、i.i.d. | 逆向归纳，`V_t = Σ_θ p(θ) max_a V_{t+1}∘g` |
| `t=T` 未到终点 → −∞ | 用有限失败支付 **当前现金 − M** 替代（`--M`，默认 1e6），并做灵敏度分析 |
| 有限 `M` 下策略可能冒险 | 平行维护成功概率表 `P_succ`，随价值最优策略传播 |
| 天气概率取值 | 第三关：无沙暴，取附录实证频率 `p=(晴0.6, 高温0.4)`；第四关：`p=(0.5, 0.4, 0.1)`，`p_沙暴` 做扫描 |

代码实际最大化的是**大失败惩罚下的单目标期望支付**。令 `τ` 为到达终点的时刻，`κ` 为失败被确认的时刻（资源不足而无合法行动，或到截止日仍未到达），则单条路径的支付为

$$
G_M=
\begin{cases}
C_\tau+\dfrac12(p_WW_\tau+p_FF_\tau),&\tau\le T,\\[6pt]
C_\kappa-M,&\text{失败}.
\end{cases}
$$

目标为

$$
\boxed{\max_\pi\;\mathbb E_\pi[G_M]}.
$$

因此 `P_succ` 是该标量目标最优策略对应的伴随统计量，并非程序首先最大化的量。当前程序**不是**严格的字典序优化 `max(P_succ, 收益)_lex`；当 `M` 足够大时，它只是对“安全优先”的数值近似。

## 2. 算法：逆向归纳 DP

### 2.1 状态分解 `V = C + U`

状态 `(v, W, F, C)` 中资金 `C` 范围太大，不宜作表的一维。观察：

- `J` 对 `C` 线性（斜率 1）；
- 改变 `C` 的操作只有挖矿 `+R` 与购买 `−p·q`，都是加性常数；
- 这两关资金约束从不真正起作用（瓶颈是 1200 kg 负重；轨迹回放验证全程 `C>0`）。

因此分解

$$
V_t(v,W,F,C) \;=\; C + U_t(v,W,F)
$$

`U` 只存**未来净资金贡献**：挖矿 `+R`、村庄购买 `−p·q`、终点退款 `+½(p_W W+p_F F)`、失败残差 `−M`。失败时当前现金仍由分解式中的 `+C` 保留，所以完整失败支付是 `C−M`。表维 `(T+1) × (n+1) × 401 × 601`，`float32`。

### 2.2 递推

下标约定与 Q1 相同：`s_t` 为第 `t` 天**结束时**状态；第 `t+1` 天的行动把 `s_t` 送到 `s_{t+1}`。

```
U[T][end, W, F] = ½(p_W W + p_F F);  U[T][v≠end] = −inf      # 终值 / 实现哨兵
P[T][end] = 1

for t = T−1 … 0:
    U[t][end] = 终值;  P[t][end] = 1                          # 已在终点即完成
    for v ≠ end:
        for θ with p(θ) > 0:
            U_θ = −M 的平面                                   # 该天气下的 max_a
            stay/mine/move 逐动作改进 U_θ（见 2.3）
            if mode == start_of_day 且 v ∈ 村庄:
                U_θ ← LiftUp(U_θ; 村庄价)                     # 早晨购买
            U[t][v] += p(θ) · U_θ   （P 同理）
```

`θ` 分支内没有任何行动可行的格子保持 `−M`（与状态现金合并后即 `C−M`），不可达格（`−inf`）仅作为实现哨兵而不传播。行动在沙暴天不含 `move`。

### 2.3 行动施加 `_apply_action`

对目的层 `src = U[t+1][u]`（或其在 after_arrival 下的抬升版），消耗 `(cw, cf)`、收益 `income`：

```
out[cw:, cf:] = max(out[cw:, cf:], src[:W+1−cw, :F+1−cf] + income)
```

即 `out` 按**行动前库存** `(W,F)` 索引，读取 `src` 的**行动后库存** `(W−cw, F−cf)`。整张 `(W,F)` 平面一次 numpy 切片完成。

### 2.4 村庄购买抬升 `LiftUp`（reverse knapsack）

购买把库存 `(W,F)` 映射到**更高**库存 `(W+q_W, F+q_F)`，线性成本：

$$
\text{lifted}[W,F] \;=\; \max_{q\ge 0}\; U[W+q_W, F+q_F] - p_W q_W - p_F q_F
$$

对整张表做两次**从高到低**的一维扫描（先水后食物），成本可加、轴可分离 ⇒ 两趟精确。扫描同时维护 `origin_w/f`（取到最大的买后格），成功概率平面 `P` 在同一 origin 处取值，保证 `P` 与 `U` 最优购买严格一致。负重 mask 施加在**目标（买后）库存**上，扫描链只允许经过 mask 内格子。

### 2.5 购买时机 flag（与 Q1 同一个开关）

```python
class VillagePurchaseMode(str, Enum):
    START_OF_DAY  = "start_of_day"   # 默认；对齐 Q1 语义
    AFTER_ARRIVAL = "after_arrival"
```

- **`start_of_day`**：当天开始已在村庄 ⇒ 观察 `θ_t` 后、行动前购买。实现为**先对该 `θ` 的所有行动取 max，再对整张平面做一次 `LiftUp`**。`max` 与 lift 可交换（`lift(max_a X_a) = max_a lift(X_a)`），因此一次抬升等价于逐行动抬升；mask 恰好落在「买后/行动前」库存上，且 `W` 不足时也能表达「买到够行动」。**当天买当天即可离村**——这是正确建模 L4 村庄→矿山补给的关键。
- **`after_arrival`**：当天**结束**在村庄 ⇒ 行动后购买。把每个村庄目的层 `U[t+1][u]` 提前抬升一次（与 `θ` 无关，因为购买发生在明天天气揭晓之前）；停留在村庄结束当天同样可买。

第四关两种模式对比：`start_of_day` 的惩罚期望目标值为 12422.3，`after_arrival` 为 12414.5——到达再买少了「看天气再决定买多少」的灵活性，略低，符合直觉。

### 2.6 第 0 天购买

起点按**基准价**从 `(0,0)` 买到 `(q_W,q_F)`，成本精确，无需 knapsack：

```
obj[q] = (C_init − p_W q_W − p_F q_F) + U[0][start, q]
q0 = argmax over mask
```

### 2.7 剪枝

- 到终点最短路（BFS，忽略沙暴，乐观）：`dist(u) > T−(t+1)` 的移动跳过；
- 终点吸收：`U[t][end]` 恒为终值，不再向外行动；
- 未做跨 `(W,F)` Pareto 剪枝（同 Q1 的理由：占负重，不安全）。

## 3. 策略查询、模拟与验证

| 模块 | 职责 |
|------|------|
| `policy.py` | `best_action(day, v, W, F, θ)`：在单个实现状态上**逐点**重算每个合法行动的价值（含两种购买语义），返回 argmax 及购买量。非村庄直接读 `U[day]`；村庄购买用局部扫描（等价于单点版 `LiftUp`）。 |
| `simulate.py` | 给定天气序列（默认附录/演示序列），从 `q0` 出发逐日调用 `best_action`，产出 `DayRecord` 轨迹与实现终值。 |
| `verify.py` | ① 规则回放：消耗、邻接、沙暴禁行、矿山/村庄位置、负重、村庄价格、购买时点按模式分别施加（`after_arrival` 的消耗用**买前**库存检查）、**全程现金非负**（验证 §2.1 的假设）；② 策略一致性：每天记录的行动必须等于 `best_action` 的 argmax。 |

### 3.1 数值校验（三道独立检查）

1. **贝尔曼恒等式**：在实现轨迹访问到的每个状态上检验  
   `U[t][v,W,F] == Σ_θ p(θ)·best_action(t+1, v,W,F,θ).value`，近 5000 个状态最大偏差 0.001（float32 精度）。
2. **规则回放**：`verify.py` 不读 DP 内表，按规则重放两关演示轨迹，终值一致。
3. **蒙特卡洛**：2×10⁴ 条 i.i.d. 天气序列模拟最优策略，失败分支按 `cash−M` 计：
   - 第三关：`V0=9334.0`，MC `9334.2 ± 0.5`，成功率 1.0 = `P_succ`；
   - 第四关：`V0=12422.3`，MC `12382 ± 123`（含失败分支）；`E[值|成功]=12682` 对模型隐含值 12686；MC 失败率 3×10⁻⁴ ≈ `1−P_succ=2.6×10⁻⁴`。

   三者共同确认 DP、策略查询、模拟器语义完全一致。

### 6.1 第三关策略概要

矿山收益仅 200/天且期限 10 天，挖矿不划算：第 0 天买 54 水 + 54 食物（耗 810），沿 `1→4→6→13` 视天气直驶终点，最迟第 6 天前到达的变体均可；演示序列下第 3 天到达，剩余资源退款 160，实现值 9350。决策表显示在矿山旁时**晴天挖、高温停**、临近期限且库存偏低时**高温停留保水**等自适应行为。

### 6.2 第四关策略概要

1. 第 0 天买 228 水 + 258 食物（耗 3720，负重 1188/1200 近满载）。
2. 晴/高温推进、沙暴停留，`1→2→3→8→13→18` 约第 5 天到矿山。
3. 在矿山 18 挖矿至库存将尽（演示序列挖 5 天），返回村庄 14 补给约 170 水 + 170 食物（村庄价），再返矿山继续挖。
4. 预计期限将近时（演示序列第 23 天）启程 `18→19→20→25`，第 25 天到达终点。

决策表（部分）：

| (1, 1, 228, 258) | move:2 | move:2 | stay |
| (6, 18, 150, 160) | mine | mine | mine |
| (12, 18, 40, 45) | move:13 | move:13 | stay |

## 7. 灵敏度分析

### 7.1 失败惩罚 `M`

| M | 第三关 V0 / P_succ | 第四关 V0 / P_succ |
|---|---|---|
| 10³ | 9355.1 / 0.936 | 16032.9 / **0.000** |
| 10⁴ | 9334.0 / 1.000 | 14001.6 / 0.961 |
| 10⁶ | 9334.0 / 1.000 | 12422.3 / 0.99974 |
| 10⁹ | 9334.0 / 1.000 | 10650.8 / 1.00000 |

- `M` 偏小时「失败」代价低于冒险收益，价值最优策略主动赌死：第四关 `M=10³` 时甚至退化为「买满物资冲到矿山挖到弹尽、接受失败支付」（`P_succ=0`，惩罚目标值反而虚高）——说明 **`M` 必须显著大于正常策略间的收益差**，否则标量目标不会体现「尽量活着到达」。第三关 `M=10³` 时，策略也开始接受 6.4% 的失败率以换取更高的成功分支收益。
- `M ≥ 10⁶` 后第三关完全稳定；第四关 `M=10⁹` 时策略更保守（惩罚目标值下降、成功率显示为 1），`M=10⁶` 是兼顾「视失败为灾难」与「不过度扭曲正常收益比较」的基准取值。该选择由灵敏度分析支持，但不把模型变成严格字典序目标。

### 7.2 沙暴概率 `p_沙暴`（第四关，晴:高温 保持 5:4）

| p_沙暴 | V0 | P_succ | q0 |
|---|---|---|---|
| 0.00 | 16336.6 | 1.00000 | (228, 258) |
| 0.05 | 13802.9 | 0.99982 | (228, 258) |
| 0.10 | 12422.3 | 0.99974 | (228, 258) |
| 0.15 | 11285.6 | 0.99975 | (184, 324) |
| 0.20 | 10389.1 | 0.99968 | (188, 318) |

惩罚期望目标值对 `p_沙暴` 近似线性下降（每 +0.05 约 −1200）：沙暴既增加消耗又封锁移动。`p_沙暴 ≥ 0.15` 后第 0 天装载结构改变（多食物少水），策略整体转保守；价值最优策略对应的成功率始终保持在 0.9997 附近。

## 9. 复杂度与性能

- 状态表 `(T+1)(n+1)(W_max+1)(F_max+1)`：第三关约 3.7×10⁷ 格（≈150 MB），第四关约 1.9×10⁸ 格（≈780 MB，`float32`）。
- 每天每节点每天气约 5 次切片转移 + 村庄处一次 `LiftUp`；本机第三关 <1 s，第四关约 7 s。
- `P_succ` 滚动两层，不整表存储；`policy` 单点查询为一次局部扫描（≤401×601）。

## 10. 注意与假设

1. **资金不约束**是§2.1 分解的前提：由轨迹回放全程 `C>0` 验证成立（两关、两种模式）。
2. 购买决策视为**当天观察天气后**作出（购买属于当天行动的一部分），与 Q1 同日「买+行动」语义一致。
3. 第三关天气概率取附录 10 天的实证频率（6 晴 / 4 高温）；第四关 `(0.5, 0.4, 0.1)` 为假设值，已做 `p_沙暴` 灵敏度。
4. 演示轨迹只是策略在**一条**实现天气下的样本；`Result.xlsx` 所填为演示轨迹（第三关用附录实际天气），策略本身以决策表 `policy.best_action` 为准。
5. 三、四关邻边取自公开参考解（附件 VML 无线可解析），已对称化并核对最短路等约束。
